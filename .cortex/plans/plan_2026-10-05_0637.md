## 2. Recommended Architecture

### Snowflake-Native Stack

```
┌─────────────────────────────────────────────────────────┐
│                    Streamlit in Snowflake                │
│            (Investigation UI + Report Export)            │
├────────────┬────────────────────────┬───────────────────┤
│  Cortex    │   Cortex Search        │  Cortex           │
│  Analyst   │   (Policy Docs,        │  COMPLETE         │
│  (SQL Q&A) │    Filing Text,        │  (Evidence        │
│            │    Case Notes)         │   Synthesis)      │
├────────────┴────────────────────────┴───────────────────┤
│              Semantic View / Model Layer                 │
│         (governed, versioned metric definitions)        │
├─────────────────────────────────────────────────────────┤
│                 Deterministic SQL Layer                  │
│     Risk Signals │ Financial Metrics │ Alert Rules       │
├─────────────────────────────────────────────────────────┤
│                    Base Data Layer                       │
│  Transactions │ Accounts │ Customers │ Policies │ Cases │
└─────────────────────────────────────────────────────────┘
```

### Design Decisions

1. **Cortex Analyst + Semantic View** for governed natural-language SQL queries — ensures answers are grounded in defined metrics, not hallucinated
2. **Cortex Search** for policy/filing retrieval — provides RAG over unstructured compliance text with server-side authorization
3. **`CORTEX.COMPLETE('llama3.1-70b')`** for evidence synthesis and draft generation — with explicit provenance of sources used
4. **Deterministic SQL views** for all risk scores and financial metrics — no AI in the calculation path, AI only interprets/synthesizes
5. **Streamlit in Snowflake** for the UI — runs inside Snowflake's security perimeter, inherits role-based access

## 4. Staged Implementation Plan

### Stage 1 — Foundation (Schema + Synthetic Data)
- Create `RISKLENS` database with schemas: `RAW`, `ANALYTICS`, `CORTEX`, `APP`, `AUDIT`
- Create a dedicated `RISKLENS_ROLE` (least-privilege, not ACCOUNTADMIN) and `RISKLENS_WH`
- Define base tables: `CUSTOMERS`, `ACCOUNTS`, `TRANSACTIONS`, `WATCHLISTS`, `POLICIES`
- Load clearly labeled synthetic data (~1000 transactions, 50 accounts, 10 customers) including known suspicious patterns (structuring, velocity spikes, dormant-account activity)

### Stage 2 — Risk Engine (Deterministic SQL)
- Build SQL views for: transaction velocity (rolling windows), structuring detection (just-below-threshold patterns), dormant account reactivation, geographic anomaly scoring
- Composite risk score view combining weighted signals — all logic in SQL, fully auditable
- Threshold-based alert materialization with rule version tracking

### Stage 3 — Cortex Search + Policy RAG
- Create a `POLICIES` table with AML/KYC reference text (synthetic, clearly labeled as illustrative)
- Build Cortex Search service over policy documents
- Test retrieval with compliance-relevant queries

### Stage 4 — Semantic Model + Cortex Analyst
- Author a semantic YAML model covering transactions, risk signals, and case status
- Validate with `cortex reflect`
- Enable natural-language queries like "show accounts with structuring alerts this week"

### Stage 5 — Evidence Synthesis (LLM Layer)
- Build a Python module that: takes a risk alert, retrieves relevant transactions + policy context, calls `CORTEX.COMPLETE` with a structured prompt, returns a draft finding with explicit source citations
- Every LLM call logs: input prompt, model used, output, timestamp, and source record IDs to `AUDIT.QUERY_PROVENANCE`

### Stage 6 — Streamlit Investigation UI
- Investigation dashboard: alert queue, transaction timeline, risk signal breakdown
- Case management: assign, review, escalate, document findings
- Report export: human-reviewed findings to PDF/structured format
- Auth: enforce `CURRENT_ROLE()` checks, filter data by authorized scope

### Stage 7 — Audit & Hardening
- Query provenance logging for all AI-generated content
- Review history (who approved/rejected each finding, with timestamps)
- Rule version tracking (which scoring logic version produced each alert)
- Add disclaimers: investigation signals, not proof of fraud; no regulatory compliance claim
